# 旅迹（TripTrail）

旅迹是一款 iPhone 本地旅行规划与旅行记录 App。当前版本是可运行的原生 MVP，使用 SwiftUI、SwiftData、Photos/PhotosUI 和高德地图 URI API，不依赖第三方包。

## 已实现

- 当前行程：创建旅行、自动生成日期、继续添加天数、编辑当天标题与备注；每个行程点可就地修改地点名称、开始时间和图片/视频，媒体队列末尾用“+”继续添加，路程、时长、预约与花费等详细信息通过编辑入口维护。
- 每段安排：名称、类别、开始/结束时间、地址、交通方式、路程、游玩时长、预约信息、花费、笔记、完成状态；地点仅按当前行程点的名称/地址搜索候选项，不自动拼接行程级目的地，并自动保存导航坐标，普通用户无需手填。
- 智能录入：行程页将“选择截图”和“输入文本”作为并列入口。整项安排可从系统相簿按顺序选择多张酒店订单或导航截图，使用 iPhone 本机 Vision 识别并合并；也可粘贴或手动输入订单、导航、票务或备忘文本，直接复用同一套字段解析逻辑。“路程”字段也可单独选择一张导航截图，仅预填前往方式以及类似“4.4 公里 · 11 分钟”的路程信息。酒店内容可提取名称、地址、入住/离店时间、金额、订单号、房型和取消规则。所有录入方式都会进入同一个可编辑的预填表单，不会自动保存；用户主动点击保存后才写入行程。截图和文本不上传服务器。
- 媒体：从系统相簿选择图片和视频并显示缩略图；行程和足迹中的图片、视频按原顺序进入同一个全屏媒体查看器，可左右切换，视频可直接播放并在滑离后暂停。每个足迹景点/安排最多添加 9 个图片或视频（合计）。数据库只保存 `PHAsset.localIdentifier`，不复制媒体文件。
- 高德地图：“下一个地点”按行程顺序选取第一个未完成安排；有经纬度时从当前位置直接导航，否则按名称和地址打开高德搜索。
- 旅行足迹：采用“行程/足迹 → 某天 → 具体安排”的层级；足迹模块可独立新建并按日期自动生成每天的空白层级，也可通过整段行程的“收进足迹”建立骨架。收录页面支持行程、天、具体安排三级级联勾选，父级勾选会包含全部子级；再次收录会按本次选择同步到已有足迹，不会重复创建。
- 行程转足迹只同步日期层级以及大地点、景点、酒店、饭店等行程点的名称、类型和顺序，不复制文字、图片、视频、地址和路程等补充内容，由用户在足迹中独立完善。
- 足迹可一键同步源行程的最新骨架，不覆盖用户补写的内容；源行程已删除但包含用户内容的具体安排会保留并解除同步关联。
- 任一足迹安排都可在卡片内直接补写文字、添加图片或视频，素材添加后立即进入多图轮播；详细字段仍可通过长按菜单继续编辑。行程内容只支持单向收进足迹，不提供从足迹反向加入行程的入口。
- 分享与收藏：把行程或足迹（整段或单日）排版为分享长图，也可生成 `.triptrail` 可收藏文件。分享者可勾选是否包含照片和视频原件；接收方从微信等 App 打开文件后，可在旅迹内先预览再添加为自己的独立副本。
- 数据迁移：`.triptrailbackup` 会流式打包数据清单和相簿媒体原件；恢复时把媒体写入新手机相簿并重建本机索引，恢复前显示内容数量并二次确认。
- 其他：相簿权限管理、隐私说明、杭州示例行程、完整 App 图标。

## 相簿索引方案

App 保存系统相簿资源的本地标识，而不是照片或视频数据本身。优点是几乎不占额外媒体空间，也不会制造重复文件。相应边界：

- 用户删除原素材后，App 无法继续展示它。
- iCloud 原素材需要网络下载时，缩略图或播放会等待下载。
- App 显式从系统共享照片图库选择素材，并直接保存 PhotosPicker 返回的持久标识，不再要求选择后立即通过 `PHAsset.fetchAssets` 二次取回；若素材来源本身没有系统相簿标识，App 会显示当前权限状态和具体提示。
- 分享卡片是 App 新生成的图片，只有用户点击“保存到相簿”时才会写入相簿。

## 跨平台收藏协议

未带媒体的 `.triptrail` 是版本化 UTF-8 JSON；带媒体的分享以及 `.triptrailbackup` 使用公开的“清单 JSON + 原始媒体字节流”容器。交换包不依赖 SwiftData 或 Apple 私有结构，因此 Android、Web 等后续客户端可以实现同一协议。

- 分享行程或足迹时可选择整段或单日范围。
- 接收方打开文件后先进入只读预览，主动确认后才写入本地。
- 导入采用追加和根 UUID 去重，不覆盖接收方现有数据。
- 分享的足迹会解除分享者设备上的源行程同步关系，成为接收方可独立编辑的内容。
- 分享者可选择是否包含照片和视频。包含时只发送媒体引用 UUID 和原文件，不发送本机相簿标识；接收端写入相簿后重建索引。长图仍可供未安装旅迹的用户直接查看。

## 统一旅程底座

当前行程和旅行足迹共用同一套领域层级与操作规则：`旅程 → 某天 → 地点/具体安排`。标题、日期、地点类型、排序、地址与坐标、通用备注、媒体引用、增删改和分享结构由统一领域协议及服务处理，同时保留现有 SwiftData 实体，避免重构导致本地数据丢失。

- 行程专属：完成状态、预约信息、计划交通、预计游玩时长、预算/花费和未完成地点导航。
- 足迹专属：与源行程的同步关系、游后正文、实际路线以及用户补充的图片、视频和说明。
- 骨架同步只传递层级、日期、地点/安排名称、类型、时间与顺序；地址、路线、备注和媒体等游后内容由用户填写，不会被后续同步覆盖。
- 同一源行程只对应一个足迹容器。整段行程再次收录时会按源节点 ID 合并去重。

## 系统与机型

- 最低系统：iOS 17.0。
- 设备：仅 iPhone，布局使用自适应 SwiftUI 容器，适用于常用的小屏和大屏 iPhone。
- 开发环境：Xcode 16 或更新版本；当前工程已在 Xcode 26.6 / iOS 26.5 模拟器编译和启动验证。

## 运行

1. 打开 `TripTrail.xcodeproj`。
2. 选择任一 iPhone 模拟器运行；Debug 版会一次性加入覆盖行程、足迹、图片和视频的测试数据。
3. 真机运行前，在 Target 的 Signing & Capabilities 中选择自己的 Personal Team，并根据需要修改 Bundle Identifier。

真机导入测试可使用本地生成的 `.triptrailbackup` 文件。备份可能包含媒体原件，因此样例备份不会提交到代码仓库；恢复注意事项见 [`fixtures/README.md`](fixtures/README.md)。

项目由 `project.yml` 生成。如需重新生成：

```sh
xcodegen generate
```

运行测试：

```sh
xcodebuild -project TripTrail.xcodeproj -scheme TripTrail \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

## 高德能力边界

当前版本采用无需 SDK Key 的高德 URI API，只对下一个未完成地点发起单目的地导航或地点搜索。如果后续提供高德开放平台 iOS SDK Key，可以升级为 App 内地图、地点搜索和地理编码。
